Làm việc chung trên PATHS

Game nhập vai hành động 2D góc nhìn từ trên xuống, viết bằng Java Swing thuần. Trang này giải thích cách 5 người chia việc theo giai đoạn, ai giữ file nào và luật dùng Git. Mỗi người mở thêm file hướng dẫn riêng của mình để làm.

Cách nhóm làm việc

Chia theo giai đoạn

Dự án chia thành 4 giai đoạn. Trong mỗi giai đoạn, 5 người làm hoàn toàn độc lập, mỗi người trên nhánh Git riêng. Hết giai đoạn, Leader ghép code, chạy thử, rồi giao giai đoạn tiếp theo.

  1. Leader thông báo bắt đầu giai đoạn mới.
  2. Mỗi người mở hướng dẫn của mình và làm lần lượt các bài nhỏ của giai đoạn đó: đọc, thêm một đoạn code, chạy thử, tick.
  3. Nộp bài: commit, push, tạo Pull Request vào develop, báo Leader.
  4. Leader ghép, chạy thử cả game. Có lỗi thì báo đúng người sửa trên nhánh cũ.
  5. Trong lúc chờ: sửa lỗi Leader báo, đọc trước giai đoạn sau, sưu tầm tài nguyên (ảnh, âm thanh).
Lý thuyết
Vì sao làm độc lập mà vẫn ráp được?

Bộ khung ban đầu đã có sẵn tên và chữ ký mọi hàm dùng chung cho cả 4 giai đoạn. Hàm nào chưa ai viết thì trả về giá trị an toàn, ví dụ vẽ 1 ô màu tạm. Vì vậy code của bạn luôn chạy được dù người khác chưa làm xong. Mỗi người chỉ sửa file trong thư mục của mình nên khi ghép không đụng nhau.

Ngày đầu tiên

  1. Leader gửi địa chỉ repo trên GitHub và mời bạn vào repo.
  2. Mở file hướng dẫn của bạn (bảng dưới), làm mục "Ngày đầu tiên: cài đặt": cài JDK, Git, IntelliJ; clone repo bằng IntelliJ; chạy thử Main.java.
  3. Đọc mục "Tài nguyên bạn cần sưu tầm" để biết mình cần tìm ảnh gì.
  4. Chờ Leader báo bắt đầu Giai đoạn 1.

Tài nguyên sưu tầm

Game chạy được hoàn toàn bằng hình vẽ trong code. Ảnh và âm thanh sưu tầm là lớp "trang điểm" thêm vào ở Giai đoạn 3 và 4: có file đúng tên trong res/ thì game dùng, không có thì vẫn vẽ như cũ.

Dev 3Ô đất: cỏ, nước, tường, cây...res/tiles/

  • Nơi tìm ảnh: itch.io (Game assets, lọc Free), OpenGameArt.org, Kenney.nl. Âm thanh: Freesound.org, Pixabay.
  • Nên chọn cùng một kiểu: pixel-art góc nhìn từ trên xuống, ô 16×16 hoặc 32×32, để ảnh của 5 người đặt cạnh nhau không lệch tông.
  • Mỗi người ghi nguồn (tác giả, đường link) vào file NGUON.txt trong thư mục của mình để nhóm trích dẫn trong báo cáo.

Ai giữ file nào

Chỉ chủ file được sửa file đó. Muốn dùng code của người khác thì gọi hàm, không sửa file của họ.

Sơ đồ lớp chính

  • Trừu tượng: GameObject, Entity, Monster là lớp abstract; IDamageable, IInteractable, AIState, GameState là interface.
  • Kế thừa: Player và mọi quái dùng lại di chuyển, va chạm, máu từ Entity.
  • Đa hình: World gọi m.draw() cho mọi quái, Java tự chạy đúng hình của Slime/Skeleton/Boss. Phím E gọi onInteract() cho rương hay NPC đều được.
  • Đóng gói: máu chỉ đổi qua takeDamage()/heal(); giao diện chỉ lộ showMessage().

Luật Git của nhóm

6 luật

  1. Không ai push thẳng lên develop hay master. Mọi thay đổi đi qua Pull Request.
  2. Mỗi giai đoạn 1 nhánh mới từ develop mới nhất, đặt tên feature/devN-gdX (ví dụ feature/dev3-gd2).
  3. Khi commit, chỉ tick (hoặc git add) đúng file trong thư mục của mình. Không dùng git add ..
  4. Lời commit có dạng [DevN][GDX] Mo ta ngan.
  5. Chạy file thử riêng của mình thấy đúng rồi mới push.
  6. Không đổi tên, không xóa hàm public có sẵn. Cần hàm dùng chung mới thì nhắn Leader.

Thao tác Git mỗi giai đoạn

Hướng dẫn của mỗi người ghi sẵn từng bước ở đúng chỗ cần làm, theo 2 cách: bấm chuột trong IntelliJ hoặc gõ lệnh. Tóm tắt:
